Problem Statement & Motivation

The Challenge of Concurrent Synchronization

"Implement and visualize different synchronization strategies to prevent deadlock and starvation among competing processes/threads."

⚠️ The Deadlock Dilemma

When multiple concurrent processes compete for bounded, non-preemptible resources, circular dependencies can freeze the entire operating system permanently.

🎯 Our Core Engineering Goals

  • Execute genuine C POSIX threads (`pthreads`) rather than frontend mockups.
  • Demonstrate and detect circular wait under controlled conditions.
  • Implement and prove Dijkstra's Resource Ordering technique.
  • Guarantee starvation freedom via a Fair FIFO Monitor.
Theoretical Model

The Dining Philosophers Problem

Formulated by Edsger W. Dijkstra (1965) to model multi-process resource competition.

🍴 System Invariants

  • 5 Philosophers (Threads $P_0 - P_4$) alternating between Thinking, Hungry, Waiting, and Eating.
  • 5 Forks (Shared Resources $F_0 - F_4$) placed between adjacent philosophers.
  • Dining requires both adjacent forks simultaneously.
  • At most 2 philosophers can dine concurrently ($\lfloor 5/2 \rfloor = 2$).

🔒 Synchronization Primitives

// Each fork is a mutual exclusion lock pthread_mutex_t fork_mutex[5]; // Philosopher i needs forks: int left_fork = i; int right_fork = (i + 1) % 5;

Operating Systems Primitives

Threads, Mutexes & Critical Sections

🧵 Thread Lifecycle

Created with `pthread_create()`. Each philosopher thread executes an event loop with non-blocking sliced sleeps (20ms) for instantaneous pause/resume/stop responsiveness.

🛡️ Critical Section Protection

  • Fork Mutexes: Enforce invariant that no fork is owned by two philosophers simultaneously.
  • State Mutex: Protects aggregate metrics and snapshot generation against race conditions.
  • Clean Join: All threads joined via `pthread_join()` on shutdown; zero orphans.
Deadlock Analysis

Deadlock & Resource Ordering Prevention

⚠️ The Deadlock Scenario

In Naive Left-First mode, every philosopher locks their left fork. All 5 philosophers hold 1 fork and wait for the second fork.

P0 -> F1 -> P1 -> F2 -> P2 -> F3 -> P3 -> F4 -> P4 -> F0 -> P0 All 4 Coffman Conditions Hold: 1. Mutual Exclusion | 2. Hold & Wait 3. No Preemption | 4. Circular Wait

🛡️ Resource Ordering Solution

Impose global total order: $F_0 \prec F_1 \prec F_2 \prec F_3 \prec F_4$. Every philosopher acquires $\min(L, R)$ before $\max(L, R)$.

P4 acquires F0 FIRST, then F4! RAG is guaranteed to be a DAG. Condition 4 (Circular Wait) is broken. Deadlock is mathematically impossible!
Starvation Prevention

Starvation vs. Fair FIFO Monitor

❓ Why Resource Ordering Can Starve

Deadlock prevention does not guarantee fairness. Asymmetric thread scheduling can allow alternating pairs ($P_0, P_2$) to eat repeatedly while $P_1$ starves.

⭐ Fair FIFO Monitor Mechanism

  • Hungry philosophers are enqueued in exact arrival order.
  • Admission granted only if both forks are free AND no earlier queued philosopher needs either fork.
  • Condition variables (`pthread_cond_t`) wake threads in FIFO order.
  • Guaranteed Starvation Freedom under finite eating duration.
